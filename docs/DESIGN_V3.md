# TestWell V3 디자인

## 결정

C. **절제된 검사 시스템**을 선택했다. 큰 왼쪽 정렬 제목, 구조적 그리드, 얇은 선, 문항과 검사지의 관계를 설명하는 HTML 도식이 기준이다. 검정 Hero 뒤에 크림색 설명 영역을 두는 것은 정보의 종류를 구분하기 위한 면 처리다. 다른 방향의 대형 제품 미디어나 동등한 역할 카드 묶음을 혼합하지 않는다.

[GO 판단](LANDING_GO_NO_GO.md), [현재 화면 감사](CURRENT_STATE_AUDIT.md), [레퍼런스 감사](REFERENCE_AUDIT.md)를 작성·확인한 후 구현했다.

## Hero와 CTA

- 분류: 심리검사 · 학습평가.
- 제목: **검사를 만드는 일부터, / 참여와 결과 확인까지.**
- 부제: TestWell의 온라인 플랫폼 정의와 제작자·참여자 역할을 두 문장으로 설명.
- 노랑 주 CTA: **문항 관리에서 시작** → `/q_bank/question`.
- 보조 CTA: **내 검사 확인** → `/survey/inventory`.
- 결과 확인은 헤더에서 직접 진입. 모바일은 메뉴 열기와 링크 선택의 두 클릭으로 로그인 경로에 도달한다.
- Hero 링크는 두 개뿐이며, 제작 시작 화면과 로그인 필요를 각각 설명한다.
- 헤더는 이용 안내/내 검사/결과 확인/로그인. 제작 CTA를 다시 강조하지 않는다.

## 섹션 구조

헤더·푸터를 제외한 주요 영역은 네 개다. 의미가 겹치는 역할·기능·과정 섹션을 따로 늘리지 않았다.

1. Hero와 참여자 진입: 정체성, 대상, 두 출발점.
2. 제작 도구 안내: 문항→검사지 관계와 별도 참여자 관리 도식 + 목적 중심 설명 + 실제 메뉴 링크. 관리 관계이지 필수 선형 절차가 아니다.
3. 일반적인 검사 원칙: 무엇을 알아보는지/어떻게 점수를 정하는지/어디까지 해석 가능한지. 제품 기능 설명과 면·라벨로 분리.
4. 다음 경로: 검사 탐색은 공식 서비스, 이용 질문은 문의. 제작 CTA를 그대로 반복하지 않는다.

## 제품 화면과 삽화

로그인 후 실제 화면을 확인하지 못해 스크린샷을 사용하지 않았다. ProductFlow는 semantic figure·HTML 텍스트와 기존 lucide 아이콘으로 직접 제작했다. 입력란, 탭, 저장 버튼, 그래프, 검사명, 가격, 결과 점수가 없어 작동하는 제품 UI로 포장하지 않는다. 캡션이 설명 도식임을 명시한다. 기존 삽화는 소스 자산과 이력을 보존하되 렌더링에서 제외했다. 외부 자산 다운로드나 새 이미지 생성은 필요하지 않았다.

Tailwind의 기존 브랜드 토큰을 유지한다. 컴포넌트 CSS는 같은 핵심 색을 사용하고 미세 본문 색만 위 표에 명시했다. 노랑은 주요 CTA와 첫 분류 라벨·워드마크 점에만 제한한다. 카드·그림자·그라데이션·유리 효과는 사용하지 않는다.

## 타이포그래피와 간격

기존 Pretendard와 시스템 폰트 폴백을 유지. 본문 16–18px, 설명·링크 최소14px. Hero 최대64px, 모바일 약30px, 제목 line-height1.23–1.35. 긴 한국어는 keep-all과 overflow-wrap을 함께 사용한다. 제목에 무리한 단어별 강제 줄바꿈은 하지 않는다. 내용 너비 최대1200px, 좌우 여백48/32/24px. Hero는 내용 높이를 따르며 viewport 강제 높이를 사용하지 않는다.

## 모바일 전환

1024px 미만에서 메뉴 접기, 640px 미만에서 한 열 구성. 문항과 검사지 관계는 작은 화면에도 좌우로 읽을 수 있고 참여자 관리만 다음 행으로 이동한다. 기능 설명은 목록으로 쌓이며, 기능 이동 링크는 44px 이상의 높이를 확보한다. 제작 버튼은 모바일 전폭. 참여자 링크는 Hero 안에서 바로 보인다.

## 접근성과 성능

h1 하나, h2/h3 순서 유지, main 건너뛰기 링크, label 있는 nav/figure/aside, 장식 SVG aria-hidden 적용. 메뉴는 aria-expanded/controls, Escape 닫기와 트리거 포커스 복귀, 외부 클릭/포커스 이탈/데스크톱 전환 닫기를 지원한다. 모션 진입을 제거하고 MotionConfig reducedMotion=user 및 CSS 감소 동작 규칙을 유지한다. 고정 크기의 아이콘 이외 이미지 로딩이 없어 새 이미지 CLS 요인은 없다. 웹폰트는 기존 CDN 의존이 남아 있으므로 오프라인 동일 렌더링과 현장 성능 점수는 보장하지 않는다.

색상 대비와 반응형/키보드의 실제 검사 결과는 artifacts/after-checks.json, 캡처는 artifacts/screenshots에 저장한다.

## 2026-09-08 후속 수정 — 제작 전 짧은 안내

앞서 기록한 독립 “일반적인 검사 원칙” 섹션과 세 항목, 긴 보증 제외 문구는 화면에서 제거했다. 현재 화면은 제작 안내 안의 작은 aside로 통합했다.

- 라벨: 문항을 준비하기 전에
- 제목: 이 검사로 무엇을 알고 싶나요?
- 본문: 얼마나 자신 있는지 묻는 질문과, 무엇을 알고 있는지 확인하는 문제는 다릅니다. 알아보려는 내용을 먼저 정하고, 그에 맞는 문항과 결과 해석의 기준을 함께 준비하세요.

이 예시는 자신감에 대한 자기보고와 지식 확인이 다른 대상을 다룬다는 준비 안내이며, 실제 검사 사례·검증 완료·자동 분석 제공 주장이 아니다. 척도화 자체의 정의로도 사용하지 않는다. 주요 영역은 Hero, 제작 도구(준비 안내 포함), 다음 경로의 세 개로 줄었다. 제목은 제작 섹션의 하위 h3이고, 별도 배경 면을 추가하지 않았다.
