# 교수님 설명용 요약

작성일: 2026-09-08. 제품 설명과 이번 랜딩 제작의 판단을 구분한다. 로그인 후 업무 수행, 개별 검사 검증, 실제 사용자 실험은 이번 설명의 근거에 포함하지 않는다.

## TestWell 한 문장 설명

**TestWell은 심리검사와 학습평가를 만들고, 참여하고, 결과를 확인하는 온라인 플랫폼입니다.**

## 왜 랜딩페이지가 필요한가?

공개 메인에서는 검색과 상품 목록이 먼저 보이고 제작 기능은 메뉴에 들어 있다. 신규 방문자는 검사 구매·참여 서비스라는 인상만 받을 수 있다. 이번 랜딩은 문항·검사지·참여자 관리와 참여·결과라는 전체 역할을 설명한 뒤 실제 기능으로 연결한다. 이는 화면에 근거한 커뮤니케이션 문제의 가설이다. 사용자 이해도가 개선되었는지는 후속 사용자 테스트로 확인해야 한다.

**판정은 GO다.** 기존 검색 목록을 복제하지 않고 역할 안내를 맡는다는 조건에서 별도 페이지의 이유가 있다. 실제 배포 시에는 기존 이용자의 기능 주소를 우회시키지 않아야 한다. 모든 이용자가 랜딩을 한 번 더 거치도록 강제하면 목적에 어긋난다.

## 기존 화면과 역할 차이

| 기존 TestWell 공개 화면 | 새 랜딩 |
| --- | --- |
| 검사 검색·상품 목록과 기능 메뉴 제공 | 서비스 정체성과 제작자·참여자 역할 설명 |
| 검사나 이용 목적을 알고 찾아온 이용자에게 탐색 경로 제공 | 처음 온 사람이 시작할 곳을 선택하도록 안내 |
| 실제 기능으로 이동하는 기존 서비스 입구 | 동일한 실제 기능으로 직접 연결하는 설명 입구 |

새 기능이나 새로운 서비스 운영체계를 만든 작업은 아니다. 제품을 이해하고 올바른 경로를 찾도록 공개 설명을 고친 작업이다.

## 왜 이 디자인인가?

**C. Minimal assessment system**을 선택했다. 큰 글자와 얇은 선, 구조적 그리드로 문항·검사지·참여자의 관계를 읽게 한다. 검정 Hero는 브랜드의 첫 인상을 유지하고, 크림색 기능 영역은 읽는 리듬을 바꾼다. 노랑은 주요 행동과 핵심 정보에 제한한다.

기존 인물 삽화는 분위기를 주지만 검사 제작 구조를 설명하지 못해 제외했다. 대신 HTML 도식이 공개 기능의 관계를 설명한다. 도식은 실제 편집 화면이나 작동 데모로 포장하지 않는다. 로그인 뒤 제품 화면을 확보하지 못한 상태에서 그럴듯한 대시보드를 만드는 것보다 확인 범위가 명확하다. 레퍼런스의 문구·제품 화면·삽화를 복제하지 않고 정보 위계와 여백 원리를 적용한다.

## 척도화를 어떻게 이해하고 반영했는가?

척도화는 응답에 숫자를 붙이거나 합산하는 것과 동일하지 않다. 관찰한 반응이나 수행과 관심 특성의 관계를 규칙 또는 모형으로 표현하여 해석 가능한 척도로 나타내는 과정으로 이해한다. 점수화는 정해진 채점 규칙으로 점수를 만드는 작업이고, 타당화는 특정 해석과 사용을 뒷받침하는 근거를 검토하는 과정이다.

페이지에서는 독립적인 원칙 체크리스트를 없애고, 제작 도구 안내 끝에 짧은 준비 질문을 붙였다. 태도·경험을 묻는 문항과 지식·수행을 확인하는 문제를 구분해, 측정하려는 내용에 맞게 문항과 해석 기준을 준비해야 한다는 뜻을 전달한다. TestWell이 자동 척도화나 타당화 분석을 제공한다고 말하지 않는다. 세부 용어 구분은 [포지셔닝 문서](TESTWELL_POSITIONING.md)에 남겼다. 해석과 사용에 대한 근거 원칙은 [AERA·APA·NCME의 공식 Standards](https://www.testingstandards.net/uploads/7/6/6/4/76643089/standards_2014edition.pdf)를 참고했다.

## 현재 기능과 향후 방향

현재는 공개 자료에 있는 문항·검사지·그룹 관리, 참여·결과 경로를 소개한다. 학습용 문제의 점수와 결과 제공은 공개 안내 범위로 설명한다. 자동 채점의 구체적인 방식, 문항반응이론 분석, 신뢰도 분석, 자동 척도화와 규준 산출은 확인하지 못했으므로 제외한다. 이를 ‘곧 제공’으로 바꾸지도 않는다. 향후 확장하려면 기능 실물과 해석 근거를 별도로 확인해야 한다.

## 예상 꼬리질문과 답변

### 기존 홈페이지를 고치면 되지 않나?

가능하다. 별도 URL이 본질적인 목표는 아니다. 지금은 기존 기능 코드를 바꾸지 않고 설명을 검토할 수 있는 랜딩 저장소에서 구현한다. 운영 단계에는 이 설명을 기존 첫 화면에 통합할지 별도 진입 주소로 둘지 결정해야 한다.

### 누구를 가장 먼저 설득하려는가?

TestWell을 처음 접한 제작자·운영자가 서비스 범위를 이해하는 것이 주요 과제다. 동시에 기존 참여자에게 설명을 강요하지 않도록 내 검사와 결과의 직접 경로를 유지한다. 직업이나 전공보다 수행할 일을 기준으로 나눈다.

### 왜 검색창을 없앴나?

검사 이름을 모르는 첫 방문자에게 검색이 서비스 설명을 대신할 수 없기 때문이다. 기존 공개 메인에 검색이 있으므로 새 랜딩에서 중복하지 않는다. 공개 상품 목록을 대표 사례로 복제하는 것도 제외했다.

### 일반 설문 도구와 정말 다른가?

심리검사·학습평가의 맥락과 문항·검사지·그룹, 참여·결과의 구조를 설명할 수 있다. 그러나 다른 제품에도 유사 기능이 있으므로 독점성이나 성능 우위는 주장하지 않는다. 차별성은 확인 가능한 사용 목적에서 설명한다.

### 계량심리 전공자로서 기여한 부분은 무엇인가?

문항 작성, 점수 산출, 척도 구성과 해석 근거를 혼동하지 않도록 문구의 범위를 정했다. 검사지를 구성하는 소프트웨어가 자동으로 검사의 타당성을 보장하는 것처럼 읽히지 않게 한 점이다. 전공 배경 자체를 제품 품질 보증으로 사용하지 않았다.

### TestWell이 척도화를 지원한다는 말인가?

현재 기능으로 확인하지 못했다. 일반 검사 원칙과 제품 기능을 별도 영역으로 구분했으며 자동 척도화 문구는 없다.

### AHA Lab이 검증한 서비스인가?

공식 개발·제휴·검증 관계를 확인하지 못했다. 연구실 이름이나 로고를 품질 보증에 사용하지 않는다.

### 실제로 버튼을 누르면 기능을 쓸 수 있나?

비로그인 상태에서 실제 서비스 URL과 로그인 리디렉션의 next를 확인했다. 로그인 후 업무 완료는 수행하지 않았으므로 기능 사용 성공까지 검증했다고 말하지 않는다. 랜딩에서 해당 진입 경로는 한 번의 링크 클릭으로 도달하며 인증 절차는 별개다.

### 도식은 실제 제품 화면인가?

아니다. 공개된 기능의 관계를 설명하는 구조도다. 가짜 문항 응답, 통계 결과나 저장 동작을 넣지 않았고 실제 화면 캡처처럼 표시하지 않는다.

### 성공 여부는 어떻게 알 수 있나?

처음 보는 사람에게 Hero를 5초 보여준 뒤 서비스 종류·이용자·가능한 행동·시작 경로를 묻는다. 제작·참여·결과의 세 과제를 주고 올바른 링크를 찾는지 확인한다. 구현자의 자체 점검은 실제 사용자 연구를 대체하지 않는다. 클릭 수만 늘어난 것을 이해도 개선으로 해석하지 않는다.

### 아직 남은 한계는?

로그인 뒤 제작과 채점 기능, 실제 결과 보고서, 신규 방문자 이해도, 기존 이용자에게 미치는 배포 영향은 확인이 더 필요하다. 랜딩은 이 미확인 영역을 기능 약속으로 채우지 않고 현재 공개 범위 안에서 설명한다.
