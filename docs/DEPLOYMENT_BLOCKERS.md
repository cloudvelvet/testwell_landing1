# 공식 루트 배포 차단 항목

확인일: 2026-09-08. 상태: **운영 배포 차단(production deployment blocker)**. 디자인 승인과 로컬 검사 통과는 testwell.kr 루트 배포 승인 또는 통합 완료를 뜻하지 않는다.

## 핵심 문제

현재 `LINKS.browseTests`는 `https://testwell.kr/`이다. 로컬5175에서 “공식 서비스에서 둘러보기”를 누르면 기존 서비스로 가지만, 이 랜딩을 동일한 루트에 배포하면 자기 자신으로 되돌아온다. 현재 검사 목록의 새 운영 경로가 결정되지 않았으므로 루트 교체 배포를 진행할 수 없다.

기존 루트에는 검사 검색·상품 목록뿐 아니라 응시권 코드를 입력해 검사 또는 결과 확인으로 이어지는 진입 기능도 있다. 새 랜딩은 이 기능들을 구현하지 않는다. 새 운영 경로와 보존 방법을 확정하기 전에 기존 루트를 덮어쓰면 기능 진입점을 잃을 수 있다. 확인하지 않은 경로를 만들거나 상점 경로로 임의 대체하지 않았다. `links.ts`도 그대로 유지한다.

## 배포 전 결정·검증 표

| 항목 | 현재 확인/미결 사항 | 차단 해제에 필요한 증거 |
|---|---|---|
| 검사 탐색의 실제 새 경로 | 현재 공개 메인은 `/`; 대체 운영 주소 미확정 | 운영자가 확정한 실제 URL, 검색·목록 접근 성공, browseTests 수정 및 자기참조 없음 확인 |
| 응시권 코드 진입 | 기존 루트에 검사·결과용 코드 입력 경로가 있으나 새 배치 미정 | 코드 입력 화면 위치, 기존 코드 링크 호환성, 유효/오류 코드의 검사·결과 진입 검증 |
| 로그인 next=/ | 로그인 링크는 `/authority/login?next=/`; 루트 교체 뒤 인증 후 도착 화면 미정 | 인증 완료 후 의도한 화면 도착, 기존 로그인/로그아웃/복귀 흐름 검증 |
| 회사 Footer 정보 | 새 랜딩에는 회사명·주소·사업자등록번호·대표자 표기가 없음 | 기존 공식 정보의 정확성·유지 위치를 운영자가 확인하고 필요한 표기를 반영. 이 문서는 법률 적합성 판단이 아님 |
| 서버와 정적 페이지 통합 | 기존 서버의 실제 배포 설정을 이 저장소에서 확인하지 못함 | Django 등 기존 서버의 라우트 우선순위, Vite 산출물 제공 방식, 정적 자산 경로, 인증·API·폼·CSRF 호환성 및 롤백 절차 확인 |
| 배포 주소와 메타데이터 | 최종 공개 URL 미확정 | 최종 URL 확정 후 canonical 및 필요한 og:url 결정. 확인되지 않은 og:image는 추가하지 않음 |

## 통과 기준

위 항목의 담당자 결정과 실제 검증 결과를 기록하고, 새 탐색 URL로 소스·문서·CTA 검사 결과를 함께 갱신해야 한다. 테스트에서는 로그인 게이트의 next 보존과 인증 후 실제 도착 성공을 구분한다. 그 전까지 validation-summary.json의 productionDeployment.status는 blocked로 유지한다.

이번 정합성 정리에서는 배포·서버 라우트·인증·결제·Footer 디자인을 변경하지 않았다. 임의의 신규 URL도 추가하지 않았다.
