# 해외 레퍼런스 감사

확인 날짜: 2026-09-08. 공식 홈페이지 6곳을 웹 본문과 브라우저 Hero 화면으로 직접 확인했다. 검사·평가 2곳, 폼·설문 2곳, 제품·시각 2곳이다. 아래의 기능과 신뢰 요소는 **그 사이트가 공개 페이지에서 제시한 내용**이며 실제 기능 작동이나 주장 진위를 독립 검증했다는 뜻이 아니다. TestWell의 기능 근거로 전용하지 않는다.

## 확인 범위와 증거의 한계

- 6곳의 공식 홈페이지 본문을 직접 열어 제목, CTA, 기능 설명, 신뢰 링크와 이미지 설명을 읽었다. 모두 브라우저 스크린샷을 열람했다.
- Tally는 390×844 모바일 viewport에서도 접근성 트리와 화면을 확인했다. 헤더 축소, 단열 구성, 주 CTA 유지를 확인했다. 추가 저장한 원본 크기 화면에서도 제목·설명·CTA·폼 예시가 세로로 이어지는 구성을 확인했다. 정밀 대비 수치는 측정하지 않았다. 임시 viewport는 확인 후 해제했다.
- Questionmark의 최초 화면 일부는 로딩 상태였고, 추가 저장 시도는 15초 제한을 초과하여 파일을 저장하지 못했다. Testportal은 추가 저장 화면에서 결과 검토 패널을 확인했다. 화면 관찰은 실제 기능 조작 검증과 구분한다.
- 나머지 사이트의 모바일 화면과 로그인 이후 제품 조작은 확인하지 않았다. 색상·배치 판단은 관찰한 Hero에 한정하며 전체 페이지의 모션·섹션 리듬을 실측했다고 주장하지 않는다.
- 번들 Playwright와 설치된 Chrome으로 아래 감사용 화면 6개를 저장한 뒤 모두 직접 열어 확인했다. 새 의존성을 추가하지 않았다. 캡처는 감사 증거이며 외국 사이트의 이미지·영상·로고·코드를 제품 자산으로 전용하지 않았다.
- 실제 신규 방문자를 대상으로 한 시간 측정은 하지 않았다. 아래의 빠른 이해 평가는 연구자의 구조 판단이다.

## 사이트별 판단

### Questionmark: 기능을 관계로 묶는 정보구조

Hero에서 기업 평가 플랫폼이라는 범주는 비교적 빠르게 식별된다. 본문은 관리, 제작, 실시, 보고를 연결하고 상세 기능은 별도 페이지로 보낸다. 전문성을 수식어에만 기대지 않고 구체적인 작업 범주로 설명하는 원리를 참고한다. 다만 TestWell에 동일한 전체 평가 수명주기 기능이 있다고 해석할 수 없다. 문항·검사지·그룹은 **필수 순서가 아닌 관련 기능**으로 표시하며 공개 서비스에서 확인되지 않은 관리 기능을 추가하지 않는다. 제품 시각 세부와 모바일 동작은 확인하지 않았다.

### Testportal: 제작자 소개를 읽지 않아도 참여할 수 있는 경로

제작자 가입 Hero 아래에 응시자를 위한 별도 진입 영역이 있다. 기능을 탐색하려는 방문자와 이미 검사 참여 목적이 있는 방문자를 구분한다는 점을 채택한다. TestWell에서도 참여자가 소개를 모두 읽지 않고 자신의 검사와 결과로 이동할 수 있어야 한다. 접근 코드 입력과 무가입 응시는 해당 서비스의 방식이므로 옮기지 않는다. 조작 성공률이나 응시 편의가 실제로 더 좋다는 사용자 실험은 수행하지 않았다.

### Tally: 짧은 설명과 구체적인 예시

Hero는 무엇을 만드는 도구인지, 어떤 행동을 할지 곧바로 드러낸다. 뒤이어 문서처럼 질문을 입력한다는 조작 설명과 입력 유형 예시를 배치한다. TestWell에는 짧은 문장과 관련 기능을 서로 가까이 놓는 원리를 적용한다. 무료·무제한·개인정보 보호 주장과 캐릭터는 가져오지 않는다. 모바일에서는 일부 탐색 항목을 줄이고 핵심 문장과 제작 CTA를 남긴다. 장식의 단순화와 단열 흐름을 참고하되 정보의 의미를 삭제하지 않는다.

### Fillout: 기능 설명에 구체적인 작업 근거를 붙임

현재 Hero는 AI 요청 입력을 전면에 두며 배경도 화려하다. 이 첫 화면을 TestWell의 시각 기준으로 선택하지 않는다. 본문의 제작·응답 수정·분석 등 행동과 화면을 묶는 설명 방식만 참고한다. TestWell에서 실제 제품 캡처를 확보하지 못한 부분은 합성 관리 UI 대신 확인된 기능 관계를 HTML로 그린다. 그 도식을 실제 제품 화면이라고 부르지 않는다.

### Linear: 정보 위계가 만드는 시각적 질서

확인된 Hero는 큰 좌측 제목, 짧은 설명, 실제 작업 맥락으로 이어진다. 검정·중성 회색·흰색, 얇은 경계가 정보 계층을 만든다. TestWell에서는 이 원리를 기존 검정·노랑 정체성과 크림 안내 면에 맞게 재해석한다. 제품 화면을 흉내 내기 위한 이슈 목록·수치·그래프는 추가하지 않는다. 한국어 제목은 절제된 크기로 유지하고 모션을 최소화한다.

### Framer: 시각 후보 비교 후 제외

현재 첫 화면은 AI 디자인 에이전트라는 포지션과 큰 미디어를 강조한다. 주·보조 행동의 구분은 명확하지만, TestWell에는 영상의 비중과 AI 약속이 맞지 않는다. 제품 설명 뒤에 화면 근거를 놓는 원리는 이미 다른 선택지에서 충족되므로 최종 디자인의 별도 원천으로 섞지 않는다.

## 최종 선택과 단일 컨셉

최종 시각 방향은 **C. 절제된 검사 시스템(Minimal assessment system)** 하나다. 해외 외형의 합성이 아니라 내용의 위계를 설계하는 원리만 선택한다.

| 역할 | 최종 선택 | 적용 원리 |
|---|---|---|
| 정보구조 1 | Testportal | 제작자 소개와 참여자 바로가기를 분리 |
| 정보구조 2 | Questionmark | 실제 기능 간 관계를 작업 언어로 설명 |
| 제품 설명 1 | Tally | 짧은 설명과 관련 예시를 가까이 배치 |
| 제품 설명 2 | Fillout | 기능 주장마다 확인된 작업 근거를 연결 |
| 시각 디자인 | Linear | 중성색·절제된 큰 타입·얇은 선·정렬 |
| 모바일 | Tally | 단열 순서와 핵심 행동을 유지하고 장식을 축소 |

### TestWell 재해석 규칙

- 검정 Hero와 크림 작업 안내를 **동일한 구조적 그리드** 안에서 사용한다. 다른 디자인 방향을 혼합한 것이 아니라 설명의 구획을 나누는 중성 면 처리다.
- 노랑은 주 행동과 필요한 핵심 표시로 제한한다. 레퍼런스의 고유 색 조합을 복사하지 않는다.
- 장식 삽화는 제거한다. 문항·검사지·그룹의 관계를 공개 메뉴에 기반한 HTML 도식으로 설명한다. 문항 검증 완료나 점수 분석을 암시하는 가짜 상태·그래프는 만들지 않는다.
- 도식은 기능 관계이며 강제된 작업 순서나 실제 제품 스크린샷이 아니다. 확인되지 않은 단계 의존성을 화살표로 확정하지 않는다.
- 삭제한 검색창과 정적 검사 카탈로그를 복원하지 않는다. 기존 서비스 진입을 방해할 입력 작업을 추가하지 않는다.
- 검사 품질의 신뢰도·타당도와 제품의 편의성을 구분한다. 고객 수, 인증, 기관 관계, 자동 분석 능력은 외부 사례에서 가져오지 않는다.
- 여러 참고 사이트가 기능 설명 원리에 기여하더라도 최종 시각 언어는 하나로 유지한다. 둥근 카드 반복, 유리 효과, 그라데이션, AI 이미지, 반복 영어 태그는 채택하지 않는다.
